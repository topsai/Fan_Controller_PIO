# 单芯片串口 HIL 实时测试系统设计

## 目标与边界

本项目包含 C3 基础遥控器、C3 接收器和 S3 高级遥控器三份独立固件。HIL 每次运行目标板自身的
`setup()` 和 `loop()`，不使用第二块模拟 MCU，不另写简化业务主程序。

HIL 只在真实输入边界增加可控输入，在物理输出末端增加安全锁，并提供状态观测。自动测试不能代替
ESP-NOW 射频、天线、实体按键、显示像素、传感器接线、VESC UART 电气和真实电机动作测试。

## 构建隔离

保留 `transmitter`、`receiver`、`s3_transmitter` 和 `s3_transmitter_new_pcb` 正式环境，新增对应的
`*_hil` 环境并定义 `FAN_CONTROLLER_HIL`。正式环境不编译 HIL 解析器、协议文字、输入注入、状态响应或
输出解锁入口。现有 `DIAG SIM*` 输入注入迁入 HIL，正式固件只保留不具备控制能力的运行日志。

## 固件架构

- `hil_protocol`：固定缓冲区 ASCII 解析器、递增序号、稳定错误码和单行 JSON 响应。
- `hil_runtime`：角色、最近命令、输入模式、输出锁和 10 秒通信看门狗。
- 接收器：真实 ESP-NOW 回调与 HIL 原始帧注入共用 `processControlFrame()`，继续执行 MAC、长度、版本、
  CRC、序号、活动控制源、三包稳定门限和 failsafe。
- 遥控器：摇杆、档位、按键及本地传感器在物理读取边界支持注入，后续映射、解锁、消抖、NVS 和 UI
  继续使用正式路径；状态帧注入与真实 ESP-NOW 回调共用解码入口。
- 输出末端：接收器锁定时 PWM 固定安全中位 duty 76、蜂鸣器关闭；遥控器锁定时禁止 ESP-NOW 控制包
  发射并关闭蜂鸣器。显示、LED 和内部业务继续运行。

## 串口协议

请求为 `HIL <sequence> <command> [arguments...]`，响应为恰好一行 JSON 并携带相同序号。最大行长固定，
处理 CR/LF、超长行、非法序号、缺失或多余参数、非法数字与未知命令，不使用 Arduino `String` 或动态
JSON 库。

通用命令包括 `PING`、`STATUS`、`OUTPUTS LOCK/UNLOCK`、`RESET` 和 `REBOOT`。接收器提供
`REMOTE FRAME/CONTROL/REPEAT/INVALID` 与 `VESC VALUE/FAULT/PHYSICAL`。遥控器提供摇杆、档位、按键、
状态帧和真实存在的传感器输入命令。不存在的功能统一返回 `unsupported`。

## 状态与安全

状态响应包括固件/协议版本、角色、运行时间、最近命令结果、输出锁和看门狗。接收器额外报告原始帧、
来源 MAC、协议版本、CRC/序号/重复状态、活动控制源、连接/failsafe、油门、档位、按钮、VESC 遥测、
期望 PWM 与实际 PWM、蜂鸣器期望与实际状态及诊断计数。遥控器报告输入模式、原始与映射摇杆、解锁、
档位、按键、连接、状态包、NVS 校准、本地传感器和显示状态。

HIL 上电、复位和重启默认锁定；10 秒无合法命令自动锁定。Python 退出和场景成功、失败、取消、异常时
均尽力发送锁定命令。自动场景默认禁止解锁，显式声明真实输出的场景还需要人工确认。

## Python 工具

`hil/` 分为协议、串口传输、场景运行器、命令行入口和 tkinter 仪表板。界面未连接时完整打开，所有实时
字段显示不可用，不生成模拟数据；断开后保持页面并清空陈旧实时状态。连接后每秒查询状态、绘制曲线、
记录请求响应并显示场景进度。

报告只生成 JSON、CSV 和 Markdown。场景使用版本化 JSON，覆盖协议、输出锁、看门狗、帧校验、序号、
接管、三包门限、failsafe、按键、NVS、传感器、期望/实际输出和计时边界。

## 验证与发布

先运行 Python 与 Native 测试，再 clean build 全部正式/HIL 环境。扫描正式二进制确认不存在 HIL 标识、
命令和错误码，扫描 HIL 二进制确认协议标识存在。最后执行 `git diff --check`，在可安全识别串口时进行
实机上传和低压测试，提交推送并核对本地与远端哈希。
