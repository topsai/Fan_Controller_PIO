# 单芯片串口 HIL 实施计划

## 1. 协议核心与构建隔离

- 先写 Native 失败测试，覆盖序号、参数数量、非法数字、未知命令和超长行。
- 实现固定缓冲区协议核心和运行时安全锁。
- 新增各角色 HIL PlatformIO 环境，验证正式/HIL 编译宏隔离。

## 2. 接收器真实路径接入

- 先写失败测试定义原始 v1/v2 帧解析、CRC、序号、重复包和输出门控。
- 抽出 ESP-NOW 帧处理入口，使真实回调和 HIL 注入共用。
- 在 PWM、蜂鸣器末端应用输出锁，保存期望与实际值。
- 增加 VESC 输入模式、状态快照和看门狗。

## 3. C3 与 S3 遥控器接入

- 先写失败测试定义注入输入模式、锁定时无线发送抑制和状态帧解析。
- 将摇杆、档位、按键和支持的传感器注入放到物理读取边界。
- 保持原有 NVS、显示、解锁、消抖和 ESP-NOW 业务路径。

## 4. Python 协议、传输与报告

- 先写失败的 `unittest`，覆盖请求序号、JSON、错误响应、超时、连接生命周期、断言、清理与三种报告。
- 实现 `protocol.py`、`transport.py`、`runner.py` 和命令行入口。
- 添加版本化场景和报告目录忽略规则。

## 5. tkinter 仪表板

- 先写未连接初始化、无串口打开、断开保留和无假数据测试。
- 实现连接、安全、遥控、输入、状态、曲线、场景和日志区域。
- 按固件角色启用支持的控制，不支持项清晰显示不可用。

## 6. 文档、回归与发布

- 更新项目入口、HIL 使用、命令、状态字段、安全边界和实机清单。
- 执行全部 Python 测试、Native 回归、compileall、全部正式/HIL clean build 和二进制隔离扫描。
- 在串口与板卡角色可确认时上传对应 HIL 固件并运行安全场景；否则明确记录未执行。
- 检查差异，提交、推送并核对 `HEAD` 与 `origin/main`。
