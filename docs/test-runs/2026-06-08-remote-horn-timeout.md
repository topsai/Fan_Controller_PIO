# 2026-06-08 Remote Horn Timeout Fix

## 背景

用户反馈：接收端运行一段时间后，蜂鸣器会偶发一阵长鸣，间隔大约 1 小时但不稳定。

## 根因排查

接收端蜂鸣器触发路径如下：

| 路径 | 原行为 | 风险 |
|---|---|---|
| 启动提示音 | 固定短鸣 | 无持续长鸣风险 |
| 失控保护提示 | 固定时长 | 无持续长鸣风险 |
| 链路异常提示 | 每 2 秒蜂鸣 200ms | 无持续长鸣风险 |
| 按钮 2 远程蜂鸣 | `tone(BUZZER_PIN, 2000)` 无时长参数 | 如果 `BTN:02` 状态异常保持，会持续长鸣 |

因此本次修复重点限制按钮 2 远程蜂鸣的最大连续时长。

## 修复内容

- 新增 `shouldAllowRemoteHorn()` 单元可测逻辑。
- 接收端新增 `REMOTE_HORN_MAX_MS=3000`。
- 按钮 2 远程蜂鸣单次最长 3 秒。
- 松开按钮 2 后复位保护，可以再次按下重新蜂鸣。
- 超时停止时，接收端串口输出：`远程蜂鸣超时保护，已停止`。

## 硬件复测建议

1. 两端上电并等待发射端 OLED 显示 `[OK]`。
2. 按住按钮 2 超过 3 秒。
3. 期望：接收端蜂鸣器响起后，在约 3 秒自动停止。
4. 松开按钮 2，再次按下。
5. 期望：接收端蜂鸣器可以再次响起，并仍然最多持续约 3 秒。
6. 查看 COM10 串口，期望看到 `远程蜂鸣超时保护，已停止`。

## 本次串口复测

COM10 抓取到以下关键状态：

```text
THR:   0 SPD:1 BTN:02
远程蜂鸣超时保护，已停止
```

说明接收端在识别到按钮 2 持续有效后，已经触发远程蜂鸣超时保护。

## 结论

本次代码层面已消除按钮 2 远程蜂鸣无限持续的风险，COM10 串口也已验证超时保护触发。由于用户反馈的原始现象间隔不稳定，仍建议后续长时间通电观察；如果再次出现长鸣，需要同时记录 COM10 串口中 `BTN` 字段和蜂鸣触发日志。
